# Intel IPU7 Camera Support for Linux

Native webcam support for Intel Panther Lake (PTL) laptops with IPU7 ISP and OV08X40 camera sensors. Provides a full libcamera pipeline handler with **4K (3840x2160) and 1080p output**, working through PipeWire in Firefox, Chrome, and native apps.

## What This Is

Intel's IPU7 Image Processing Unit ships in Panther Lake laptops (Dell, Lenovo, etc.) but has no mainline Linux camera support. This project provides:

- **libcamera pipeline handler** (`ipu7`) — drives the ISP hardware directly via the PSYS kernel interface
- **ISP parameter data** — captured from Intel's Camera HAL at 1080p and 4K via ioctl intercept
- **CVS driver** (`intel_cvs.ko`) — Computer Vision Sensing driver for the Synaptics INTC10E1 companion chip (required for sensor power sequencing)
- **PipeWire integration** — works as a standard camera source in any browser or app
- **Setup tooling** — module load ordering, PipeWire config, param capture tool for new resolutions

## Hardware Tested

- **Dell laptop** (Panther Lake platform)
- **Sensor**: OmniVision OV08X40 (8MP, 3856x2176 native Bayer)
- **ISP**: Intel IPU7 (ipu75xa / PTL variant)
- **OS**: CachyOS (Arch-based), kernel 6.14+
- **Output**: 3840x2160 (4K UHD) and 1920x1080 (Full HD) NV12

## Quick Start

### Prerequisites

The following packages must be installed (available in CachyOS/AUR):
- `ipu7-camera-bin` — Intel Camera HAL, AIQ libraries, firmware
- `libcamera` (built from source with the IPU7 pipeline handler)
- `linux-headers` (for DKMS driver build)

### 1. Build the CVS Driver

```bash
cd vision-drivers
make
sudo make install  # installs DKMS module
```

### 2. Configure Module Load Order

The IPU7 requires specific module ordering — the CVS driver must load before the sensor is accessed:

```bash
sudo cp ipu7-usbio-order.conf /etc/modprobe.d/
```

### 3. Install the libcamera Pipeline Handler

Copy the pipeline handler source into your libcamera tree and rebuild:

```bash
cp -r libcamera-pipeline /path/to/libcamera/src/libcamera/pipeline/ipu7
cd /path/to/libcamera
meson setup build  # or ninja -C build if already configured
ninja -C build
sudo cp build/src/libcamera/libcamera.so.0.7.0 /usr/local/lib/
sudo ldconfig
```

### 4. Configure PipeWire

```bash
mkdir -p ~/.config/systemd/user/pipewire.service.d/
cp pipewire/libcamera.conf ~/.config/systemd/user/pipewire.service.d/
# Edit the file to set LD_LIBRARY_PATH to your libcamera build directory
systemctl --user restart pipewire wireplumber
```

### 5. Test

Open Firefox and navigate to any webcam test site. The camera should appear as `\_SB_.LNK1` and support both 1920x1080 and 3840x2160.

## Architecture

```
Sensor (OV08X40, 3856x2176 Bayer)
    |
    v
ISYS (capture raw frames via V4L2)
    |
    v
PSYS ISA node (demosaic + image processing)
    |
    v
PSYS OFS node (output formatting + scaling)
    |
    v
NV12 frame buffer (1080p or 4K)
    |
    v
PipeWire → Browser / App
```

The pipeline handler manages the full flow:
1. Configures ISYS to stream raw Bayer frames from the sensor
2. Opens a PSYS processing graph with ISA and OFS nodes
3. For each frame: copies raw data into ISA input, submits ISA+OFS tasks, waits for completion
4. Copies NV12 output into the request buffer for PipeWire
5. Runs a software auto-exposure loop (32x32 Y grid sampling)

### ISP Parameters

The ISP firmware requires binary parameter blobs for each processing node terminal. These are proprietary structures generated by Intel's AIQ/AIC libraries from `.aiqb` tuning files. **They cannot be reverse-engineered by simple resolution substitution** — the binary format includes internal strides, offsets, and configuration values that are not just width/height.

Parameters were captured from Intel's Camera HAL (`libcamhal.so`) via an LD_PRELOAD ioctl interceptor at both 1080p and 4K. See `tools/capture_psys.c`.

### Terminal Buffer Sizes

Buffer sizes differ significantly between resolutions (not a simple pixel-count ratio):

| Terminal | 1080p | 4K | Description |
|----------|-------|-----|-------------|
| ISA term 19 | 3,113,472 | 24,894,720 | Processed image data |
| ISA term 18 | 196,352 | 1,558,080 | Statistics |
| OFS term 12/10 | 3,113,472 | 12,441,600 | Temporal reference |
| OFS term 8/11/6 | 130,560 | 522,240 | Noise reduction |
| OFS term 14 | 3,110,400 | 12,447,360 | NV12 output |

## Capturing Parameters for New Resolutions

To support additional output resolutions, capture the ISP parameters from the Camera HAL:

```bash
gcc -shared -fPIC -o capture_psys.so tools/capture_psys.c -ldl
LD_PRELOAD=./capture_psys.so gst-launch-1.0 icamerasrc num-buffers=5 \
    ! "video/x-raw,format=NV12,width=WIDTH,height=HEIGHT" ! fakesink
# Params saved to /tmp/hal4k_node{0,1}_term{NN}.bin
```

Convert to C headers with `xxd -i` and add to `libcamera-pipeline/params/`.

## Known Limitations

- **IR camera / LED control**: The HIMX1092 IR sensor is connected to a Synaptics CVS SoC (INTC10E1). IR sensor routing and LED control via the CVS `HOST_SET_MIPI_CONFIG` protocol are planned for a future release.
- **Auto white balance**: Not implemented (uses Camera HAL defaults from tuning file)
- **Frame processing**: Synchronous — blocks the pipeline thread. Should be replaced with async poll-based completion.
- **Sensor-specific**: Currently hardcoded for OV08X40. Other IPU7 sensors would need their own parameter captures.
